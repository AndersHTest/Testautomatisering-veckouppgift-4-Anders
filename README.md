>1. Vilka fördelar kan du se med CI & CD på din arbetsplats?<br>

> Jag skulle vilja att det fanns automatiska kontroller uppsatta för alla pull requests där kod ska slås ihop med main branch. <br><br>
>2. Vad är poängen med linting? <br><br>
> När du pushar din kod till github kan linting vara värdefullt att använda för att analysera din kod.
>Den kontrollerar syntax och ger förslag på hur man kan rätta till eventuella problem.
>Den hjälper dig att skriva bättre kod. Det finns olika verktyg att välja mellan. I detta projektet har jag använt "flake8".
>När jag läser om olika verktyg på internet så föreslår flera personer att testa ruff istället då det verktyget är snabbare.
>I ett större projekt kan man använda ett linting-verktyg och t.ex kräva att analysen måste vara OK för att en merge ska kunna göras.<br><br>
>3. Hur arbetar man med git och flera branches inom ett team? Skulle du vilja ändra något på din arbetsplats?<br><br>
>Man har en gemensam main branch dit man pushar all färdig kod. För varje ny funktion som utvecklas jobbar utvecklaren i en temporär branch och mergar den sedan till main branch när funktionen är färdigställd och godkänt. <br><br>
>4. Vad är en pull request? (kan sparas till nästa vecka)<br><br>
>En pull request är en begäran där en utvecklare frågar om kodändringar gjorda i en egen branch får mergas med main branch. Begäran skickas i t.ex Azure DevOps och teamet kan granska koden och godkänna eller avslå begäran. <br><br>
